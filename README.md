# Qurist Digital Prescription Generator

A very detailed guide for doctors, administrators, operators, and non-technical team members.

## Quick Summary

Qurist Digital Prescription Generator is a browser-based tool used to create branded digital prescriptions for Qurist / Hemp Health patients.

In simple words, this app helps a doctor:

1. Sign in with an approved Google account.
2. Fill in patient and consultation details.
3. Select one or more Qurist products.
4. Choose dosage and usage instructions.
5. Generate a professional prescription PDF.
6. Optionally upload the PDF to Google Drive.
7. Optionally save the prescription details into Google Sheets.

The app is made with normal web files:

- `index.html` controls the page layout and form.
- `styles.css` controls how the app looks.
- `script.js` controls login, form behavior, admin mode, and PDF creation.
- `sheets.js` controls Google Sheets and Google Drive saving.
- `app-config.js` stores the default dropdown values, doctor list, PDF text, and footer information.
- Image files such as `logo.png`, `footer.png`, `rx.png`, and signature images are used inside the app and PDF.

There is no backend server in this repository. There is no database inside this repository. There is no installation step using npm. The app runs directly in the browser and talks to Google services from the browser.

## What This App Does

This app is designed to make the prescription process faster and more consistent.

Instead of manually preparing a prescription every time, the doctor fills a structured form. The app then creates a PDF with the required patient details, doctor details, product recommendations, instructions, advisories, signature, seal, branding, and footer.

The app can also save a record of the prescription to Google Sheets and upload the generated PDF to Google Drive. This means the team can keep an organized prescription history without manually copying every field.

## Who This App Is For

This app is mainly for:

- Qurist doctors who create prescriptions.
- Qurist administrators who maintain doctor details, product lists, dosage options, and PDF text.
- Operations team members who need prescription records in Google Sheets and PDFs in Google Drive.
- Technical maintainers who update the app, fix issues, or change Google setup.

## What Problem It Solves

Without this app, the team may need to:

- Type prescriptions manually.
- Reuse old documents and edit them.
- Manually add doctor details and signatures.
- Manually add product names, dosages, and advisories.
- Manually upload PDFs to Google Drive.
- Manually update Google Sheets with consultation details.

This app reduces that manual work by putting everything into one guided form.

## Important Plain-English Terms

### Prescription PDF

This is the final document generated by the app. It contains the prescription information that can be downloaded, shared, or stored.

### Google Sign-In

This is the login button shown on the first screen. A doctor or admin must sign in with an approved Google account before using the app.

### Google Sheets

This is where prescription data is saved in rows, like a spreadsheet. Each saved prescription becomes a new row.

### Google Drive

This is where the generated PDF files are uploaded and stored.

### Admin Mode

This is a special section visible only to admin users. It lets admins change dropdowns, doctor records, default notes, PDF advisories, and footer text without editing code.

### App Config

This means the editable settings used by the app. Examples include complaint options, medication options, dosage options, doctor information, and PDF text.

### Local Cache

The browser stores a copy of the app settings locally. This helps the app load quickly and keep working with the last known settings if Google Sheets cannot be reached.

## Main Features

### 1. Doctor Login

The app starts with a doctor login screen.

Only approved users can enter the app. If someone signs in with an email address that is not allowed, the app blocks access.

Approved access comes from:

- The fixed allowlist inside `script.js`.
- The doctor records in the app configuration.

Admins are controlled separately. Admin users can see the `Admin Mode` button after login.

### 2. Doctor Selection

The form includes a doctor dropdown.

If the logged-in email belongs to a configured doctor, the app automatically selects that doctor. This helps prevent the wrong doctor from being selected accidentally.

Doctor information can include:

- Doctor ID.
- Doctor name.
- Designation.
- Registration number.
- Email address.
- Google Drive folder ID.
- Signature image stored through admin settings.

### 3. Patient Information Form

The app collects patient details such as:

- Order ID.
- Patient name.
- Age.
- Gender.
- Height.
- Weight.

Height can be entered in feet or centimeters. If feet are used, the app converts the height to centimeters when saving or generating the prescription.

### 4. Clinical Information Form

The app collects consultation-related information such as:

- Complaints.
- Comorbidities.
- Ongoing medications.
- Previous medical cannabis use.
- Diagnosis.

Complaints are shown as a checklist. When the doctor selects complaints, they are automatically added into the complaints text box. The doctor can still edit the text box manually.

### 5. Medication Recommendations

The doctor can add one or more medications.

Each medication entry includes:

- Medication name.
- Dosage.
- Instructions.

The default medication list includes Qurist oils, pills, and gummies. The app also supports custom medication names.

The app changes the dosage and instruction options depending on the type of product:

- Oil products show oil dosage and oil instruction options.
- Pill products show pill dosage and pill/gummy instruction options.
- Gummy products show gummy dosage and pill/gummy instruction options.

The doctor can add another medication by clicking `+ Add Another Medication`.

### 6. Additional Instructions

The app automatically fills the `Additional Instructions` box with default advice.

These notes can change based on:

- Patient gender.
- Selected medication type.
- Whether the product is oil, pill, or gummy.

For example, the app can add extra notes for female patients or product-specific aftercare instructions.

The doctor can edit the additional instructions before generating the prescription.

### 7. Follow-Up Date

The app supports follow-up information.

The default option is a 30-day follow-up. This means the app calculates a follow-up date 30 days after the prescription date.

The doctor can also choose a custom follow-up date.

### 8. PDF Generation

The `Generate Prescription` button creates a PDF and downloads it to the computer.

The PDF can include:

- Qurist branding.
- Date.
- Doctor information.
- Patient information.
- Complaints.
- Comorbidities.
- Ongoing medications.
- Previous medical cannabis use.
- Diagnosis.
- Medication recommendation table.
- Additional instructions.
- Follow-up consultation date.
- Telehealth notice.
- Travel advisory.
- Safety advisory.
- Occupational safety advisory.
- Patient agreement and disclaimer.
- Contact information.
- Doctor signature.
- Doctor seal.
- Footer image and company information.

The generated file name uses the patient name and date.

### 9. Google Drive Upload

The `Save to Google Sheets & Upload PDF` button creates the PDF and uploads it to Google Drive.

The upload folder depends on the selected doctor. Each doctor can have a different Drive folder.

After upload, the app tries to fetch a shareable Drive link. If the browser cannot fetch the link, the PDF may still have uploaded successfully. In that case, the app shows a fallback message and can open the Drive folder so the user can find the file.

### 10. Google Sheets Saving

After uploading the PDF, the app saves the prescription data to Google Sheets.

Each saved prescription becomes one row in a monthly sheet tab. The app uses the prescription date to decide the month and year.

The saved row includes:

- Date.
- Doctor name.
- Order ID.
- Patient name.
- Patient age.
- Patient gender.
- Patient height.
- Patient weight.
- Complaints.
- Comorbidities.
- Ongoing medications.
- Previous medical cannabis use.
- Diagnosis.
- Medication details.
- Additional instructions.
- Follow-up date.
- PDF URL, if available.

### 11. Admin Mode

Admin Mode lets approved admin users change app content from the browser.

Admins can edit:

- Complaint checklist options.
- Medication options.
- Doctor setup.
- Oil dosage options.
- Pill dosage options.
- Gummy dosage options.
- Oil instruction checklist.
- Pill/gummy instruction checklist.
- Default additional instructions.
- Female patient note.
- Oil-specific notes.
- Pill/gummy-specific notes.
- Footer and social links.
- Telehealth notice.
- Travel advisory.
- Safety advisory.
- Occupational safety advisory.
- Patient agreement.
- Contact information.

Admin settings are saved to a Google Sheets tab named `App Config`.

## What Happens When Someone Uses The App

This section explains the full journey in plain language.

### Step 1: The User Opens The App

The browser loads the HTML, CSS, JavaScript, and images.

The user first sees the login screen.

### Step 2: The User Signs In

The user signs in with Google.

The app reads the signed-in email address and checks whether the email is allowed.

If the email is allowed, the main prescription form appears.

If the email is not allowed, the user sees an access-denied message.

### Step 3: The App Loads Settings

The app starts with default settings from `app-config.js`.

Then it tries to load newer admin settings from Google Sheets.

If saved admin settings exist, they override the defaults.

If Google Sheets cannot be reached, the app continues using the latest local or default settings.

### Step 4: The Doctor Fills The Prescription Form

The doctor selects or confirms the doctor name, then fills the patient and clinical fields.

The doctor selects complaints, medication, dosage, instructions, notes, and follow-up details.

### Step 5: The Doctor Generates Or Saves

The doctor has two main options:

- `Generate Prescription`: creates and downloads the PDF only.
- `Save to Google Sheets & Upload PDF`: creates the PDF, uploads it to Drive, and saves the data row in Sheets.

### Step 6: The App Confirms The Result

If saving succeeds, the app shows a success popup.

If a PDF link is available, the user can copy it.

If the link cannot be fetched but the file uploaded, the user can open the Drive folder.

## How To Run The App

### Option 1: Open The File Directly

You can open `index.html` in a browser.

This may be enough for viewing the interface or testing simple PDF generation.

However, Google Sign-In and Google API features may not work correctly from every local file path. Google often requires an approved website address, called an authorized JavaScript origin.

### Option 2: Run A Simple Local Web Server

For local testing, a simple web server is better than opening the file directly.

If Python is installed, open a terminal in this folder and run:

```bash
python3 -m http.server 8000
```

Then open:

```text
http://localhost:8000
```

This serves the app from a local website address.

### Option 3: Host As A Static Website

Because this app is only HTML, CSS, JavaScript, and images, it can be hosted as a static website.

Examples of static hosting include:

- GitHub Pages.
- Netlify.
- Vercel static hosting.
- Firebase Hosting.
- Any normal web server.

When hosting publicly, the hosted website address must be added to the Google Cloud OAuth settings. Otherwise Google Sign-In may fail.

## User Guide For Doctors

This section is written for doctors and everyday users.

### 1. Open The App

Open the app link in your browser.

Use a modern browser such as Chrome, Edge, or Safari.

### 2. Sign In

Click the Google sign-in button.

Use your approved Qurist doctor account.

If access is denied, check that you are using the correct email address. If the correct email still does not work, ask an admin or technical maintainer to check the approved email list.

### 3. Confirm The Doctor

After login, check the doctor dropdown near the top of the form.

If your email is linked to a doctor record, the app may select your name automatically.

Do not generate prescriptions under another doctor unless that is intended and permitted by internal policy.

### 4. Check The Date

The date is usually filled with today's date.

Change it only if the prescription should use a different consultation date.

### 5. Enter Patient Details

Fill:

- Order ID.
- Patient name.
- Age.
- Gender.
- Height.
- Weight.

For height:

- Choose `ft` if entering feet and inches.
- Use a format like `5.11` for 5 feet 11 inches.
- Choose `cm` if entering centimeters directly.

### 6. Enter Clinical Details

Select complaints from the checklist.

The selected complaints appear in the complaints box. You can edit the box if needed.

Fill the remaining clinical fields:

- Comorbidities.
- Ongoing medications.
- Previous medical cannabis use.
- Diagnosis.

If there are no comorbidities, ongoing medications, or diagnosis details, the app may save or show `None` for those fields.

### 7. Add Medication Details

In the prescription section, select the product.

Then select the dosage.

Then choose instructions from the checklist or type your own instructions.

If the prescription needs more than one product, click `+ Add Another Medication`.

If you added a medication row by mistake, remove it using the row's remove button.

### 8. Review Additional Instructions

The app fills default additional instructions automatically.

Read them before generating the prescription.

You can edit the instructions if the patient needs something more specific.

### 9. Choose Follow-Up

The default follow-up is 30 days.

If a different follow-up date is needed, choose the custom option and select the correct date.

### 10. Generate The PDF

Click `Generate Prescription` if you only want to download the PDF.

Your browser will download the prescription file.

### 11. Save And Upload

Click `Save to Google Sheets & Upload PDF` if you want the app to:

- Generate the PDF.
- Upload the PDF to the doctor's Google Drive folder.
- Save the prescription details in Google Sheets.

During this process, the app shows loading messages such as:

- Preparing data.
- Generating PDF document.
- Authenticating with Google services.
- Uploading PDF to Google Drive.
- Saving prescription data to Google Sheets.
- Finalizing.

Do not close the browser tab while this is happening.

### 12. Copy The Link

When saving succeeds, a success popup appears.

If a PDF link is shown, click the copy button to copy it.

If the app says the PDF uploaded but the link could not be fetched, open the Drive folder and find the PDF there.

### 13. Clear The Form

After finishing one prescription, click `Clear Form` before starting a new patient.

This resets the form and scrolls back to the top.

## Technical Maintainer Guide

This section is for the person maintaining the code or Google setup.

### Technology Used

The app uses:

- HTML.
- CSS.
- JavaScript.
- jsPDF from a CDN.
- jsPDF AutoTable from a CDN.
- Google Identity Services.
- Google Sheets API.
- Google Drive API.

There is currently:

- No `package.json`.
- No npm install step.
- No bundler.
- No framework such as React, Vue, or Angular.
- No backend server in this repository.

### Browser Dependencies

The browser must be able to load:

- `https://cdnjs.cloudflare.com/ajax/libs/jspdf/2.5.1/jspdf.umd.min.js`
- `https://cdnjs.cloudflare.com/ajax/libs/jspdf-autotable/3.5.28/jspdf.plugin.autotable.min.js`
- `https://apis.google.com/js/api.js`
- `https://accounts.google.com/gsi/client`

If these scripts are blocked by a network firewall, ad blocker, privacy extension, or browser policy, the app may not work correctly.

### Google Cloud Requirements

The app relies on Google Cloud credentials.

A Google Cloud project must have:

- OAuth 2.0 Client ID for a web application.
- Google Identity Services support.
- Google Sheets API enabled.
- Google Drive API enabled.
- Authorized JavaScript origins configured for every website address where the app runs.

Examples of origins that may need to be authorized:

- Local testing origin, such as `http://localhost:8000`.
- Production website origin.
- Staging website origin, if used.

Do not place full page paths in authorized origins. Google usually expects the base origin, such as `https://example.com`.

### Google OAuth Scopes

The app requests permission for:

- Google Sheets access.
- Google Drive file access.

This allows the app to save spreadsheet rows and upload PDF files.

### Google Sheets Setup

The app uses Google Sheets for two different purposes:

1. Prescription records.
2. App configuration.

Prescription records are saved into yearly spreadsheets with monthly tabs.

Admin configuration is saved into an `App Config` tab.

### Prescription Spreadsheet Structure

Each saved prescription row contains columns for:

1. Date.
2. Doctor name.
3. Order ID.
4. Patient name.
5. Patient age.
6. Patient gender.
7. Patient height.
8. Patient weight.
9. Complaints.
10. Comorbidities.
11. Ongoing medications.
12. Previous medical cannabis use.
13. Diagnosis.
14. Medication details as JSON text.
15. Additional instructions.
16. Follow-up date.
17. PDF URL.

The app appends rows to the correct monthly tab based on prescription date.

### Monthly Tabs

The monthly sheet tab names use the format:

```text
Jan 2026
Feb 2026
Mar 2026
```

If a monthly tab does not exist, the app tries to create it.

### Yearly Prescription Files

The app can use a known spreadsheet for a year or create/find a spreadsheet by title.

The title format is:

```text
Prescription data 2026
```

For future years, a maintainer should verify that the app can find or create the correct yearly spreadsheet in the configured Drive folder.

### App Config Sheet Structure

The admin settings are saved in a tab called:

```text
App Config
```

The app stores the config as JSON text.

Because the JSON can become long, the app can split it into chunks:

```text
config:0
config:1
config:2
```

Each chunk has an `updatedAt` timestamp.

When loading config, the app reads the latest matching chunks and combines them.

### Google Drive Setup

Each doctor can have a configured Google Drive folder.

When a PDF is uploaded, it goes to the selected doctor's folder.

The app then tries to make the file readable with a link and fetch the web view link.

If the link step fails, the file may still exist in Drive. The user should check the doctor's Drive folder.

### Important Security Note

This repository contains Google configuration values in client-side files.

Client-side files are visible to anyone who can access the hosted app or repository. For that reason:

- Do not treat browser-side API keys as private secrets.
- Restrict API keys in Google Cloud as much as possible.
- Restrict OAuth origins to approved domains.
- Do not publish unnecessary spreadsheet or folder IDs in documentation.
- Review Google Drive and Google Sheets sharing permissions regularly.
- Rotate credentials if they were exposed publicly and should not have been.

This README intentionally describes where credentials are configured without repeating live credential values.

## How The App Chooses Settings

The app uses settings in this order:

1. Start with defaults from `app-config.js`.
2. Load cached settings from the browser if available.
3. Try to load the latest settings from Google Sheets.
4. Merge Google Sheets settings over the defaults.
5. Use the merged settings to render dropdowns, checklists, doctor records, notes, and PDF text.

This design means the app has safe built-in defaults but can still be updated by admins.

## Troubleshooting

### The App Does Not Open

Check:

- Are all files present?
- Is `index.html` being opened or served?
- Is the browser blocking local files?
- Are JavaScript errors visible in the browser console?

Try running a local server:

```bash
python3 -m http.server 8000
```

Then open:

```text
http://localhost:8000
```

### Google Sign-In Does Not Appear

Possible causes:

- Internet connection is unavailable.
- Google Identity Services script is blocked.
- Browser extension is blocking Google scripts.
- OAuth client ID is wrong.
- The current website origin is not authorized in Google Cloud.

### Access Is Denied After Login

Possible causes:

- The user signed in with the wrong Google account.
- The email is not in the allowed doctor list.
- The email is not in the configured doctor records.
- The admin settings did not load from Google Sheets.

Fix:

- Confirm the exact email address.
- Check doctor setup in Admin Mode.
- Check allowed email settings in `script.js`.

### Admin Mode Button Is Missing

Possible causes:

- The signed-in user is not listed as an admin.
- The user signed in with the wrong Google account.
- JavaScript failed before the admin button was shown.

Fix:

- Check the admin email list in `script.js`.
- Reload the page and sign in again.

### Doctor Dropdown Is Empty Or Incorrect

Possible causes:

- App config did not load.
- Doctor records are missing from Google Sheets config.
- Defaults in `app-config.js` were changed incorrectly.

Fix:

- Reload the app.
- Use Admin Mode to reload from Sheets.
- Check `app-config.js` default doctor records.

### Medication Dropdown Is Empty

Possible causes:

- App config did not load correctly.
- Medication records were removed in Admin Mode.
- JavaScript failed while rendering fields.

Fix:

- Reload the page.
- Reset admin settings to defaults, then save if appropriate.
- Check browser console errors.

### Generate Prescription Does Nothing

Possible causes:

- User is not logged in as an authorized doctor.
- No doctor is selected.
- Required scripts did not load.
- Browser console has JavaScript errors.

Fix:

- Sign in again.
- Select a doctor.
- Refresh the page.
- Confirm `jspdf` and `jspdf-autotable` loaded successfully.

### PDF Downloads But Looks Wrong

Possible causes:

- Image files are missing.
- Image file names changed.
- Admin text is too long for expected layout.
- Doctor signature image is missing or too large.

Fix:

- Check image files.
- Generate a test PDF after changing any branding or admin text.
- Review doctor signature configuration.

### Save To Sheets Fails

Possible causes:

- Google permission was not granted.
- Google Sheets API is disabled.
- OAuth token expired.
- Spreadsheet ID is wrong.
- User does not have permission to edit the spreadsheet.
- Monthly sheet tab could not be created.

Fix:

- Sign out and sign in again.
- Confirm Google Sheets API is enabled.
- Confirm spreadsheet permissions.
- Check spreadsheet IDs in `sheets.js`.

### PDF Upload Fails

Possible causes:

- Google Drive API is disabled.
- User does not have permission to upload to the folder.
- Drive folder ID is wrong.
- Browser blocked the request.
- Static hosting caused a CORS issue.

Fix:

- Confirm Google Drive API is enabled.
- Confirm the doctor Drive folder exists.
- Confirm the signed-in user has access to upload.
- Check folder IDs in doctor setup.
- Try from an approved hosted origin.

### PDF Upload Succeeds But Link Is Missing

This can happen when the file uploads successfully but the browser cannot fetch the shareable link.

The app may show a message with a Drive folder fallback.

Fix:

- Open the Drive folder.
- Find the uploaded PDF by patient name and date.
- Check browser console for Drive permission or CORS errors.

### Admin Settings Do Not Save

Possible causes:

- Signed-in user does not have permission.
- App Config spreadsheet ID is wrong.
- Google Sheets API is disabled.
- The `App Config` tab cannot be created or updated.
- The browser lost its Google access token.

Fix:

- Sign in again.
- Confirm admin account permissions.
- Confirm the app config spreadsheet exists.
- Confirm the user can edit the spreadsheet manually.

## Data And Privacy Notes

This app handles patient and prescription information.

That means the team should treat generated PDFs, Google Sheets rows, and Google Drive folders as sensitive.

Recommended practices:

- Give access only to people who need it.
- Review Google Drive folder sharing settings.
- Review Google Sheets sharing settings.
- Avoid sharing prescription links publicly unless that is intended.
- Keep doctor account access secure.
- Remove access when a team member no longer needs it.
- Be careful when testing with real patient data.

## Limitations

This app is intentionally simple because it is a static browser app.

Current limitations include:

- No backend server to hide Google API details.
- Google credentials and IDs are visible in browser-side code.
- Google Drive upload can be affected by browser CORS behavior on some static hosts.
- There is no automated test suite in this repository.
- There is no package manager lockfile.
- There is no build pipeline.
- The app depends on third-party CDN scripts being available.

### Add A Small Backend Or Apps Script Proxy

A backend or Google Apps Script layer could handle Drive and Sheets operations more safely and avoid some browser CORS issues.

### Move Sensitive Operations Off The Browser

Uploading files and writing spreadsheet rows from a server-side component would make permissions easier to control.

### Add Automated Tests

- Login allowlist behavior.
- Config merging.

## Glossary

### API

An API is a way for one software system to talk to another. This app uses Google APIs to talk to Google Sheets and Google Drive.

### Browser

The program used to open websites, such as Chrome, Edge, Safari, or Firefox.

### CDN

A CDN is an online place that hosts shared files. This app loads PDF libraries from a CDN.

### CORS

CORS is a browser security rule. Sometimes it blocks websites from making certain requests to other services. Some Google Drive requests can be affected by CORS when the app is hosted as a static website.

### Google Cloud Console

The Google website where API keys, OAuth clients, and enabled Google APIs are managed.

### OAuth

OAuth is the sign-in and permission system used by Google. It lets the app ask for permission to access Google Sheets and Drive.

### Origin

An origin is the base website address where the app runs, such as `http://localhost:8000` or `https://example.com`.

### PDF

A PDF is a document file that looks the same across devices and is commonly used for official documents.

### Static Website

A static website is a website made from files like HTML, CSS, JavaScript, and images. It does not need a custom backend server.

## Short Version For New Team Members

Qurist Digital Prescription Generator is a web form that doctors use to create prescription PDFs. Doctors sign in with Google, fill patient and prescription details, generate a PDF, and can save the record to Google Sheets while uploading the PDF to Google Drive. Admins can update dropdowns, doctor details, dosage choices, instructions, PDF advisories, and footer text from Admin Mode. The app is made from simple web files and depends on Google services for login, storage, and spreadsheet records.
